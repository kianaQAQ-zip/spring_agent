# 电商客服 Agent — 启动指南

> 本指南覆盖从零启动全部服务的完整步骤、验证清单与常见坑。
> 适用：Spring Boot 3.5.3 后端 + Vue3/Vite 前端 + PostgreSQL(pgvector) + doc-processor(FastAPI)。

---

## 一、环境要求（前置条件，装一次即可）

| 依赖 | 版本/路径 | 用途 | 必需 |
|---|---|---|---|
| JDK | 23（`D:\JDK23`） | 编译运行后端 | ✅ |
| Maven | 项目内置 `.tooling/maven/apache-maven-3.9.9`（离线模式） | 构建后端 | ✅ |
| Node | 22（托管版或系统均可） | 运行前端 | ✅ |
| PostgreSQL | 本机 `localhost:5432`，库 `ecom_agent`，需 pgvector 扩展 | 数据存储 | ✅ |
| `DASHSCOPE_API_KEY` | 阿里云百炼 key | LLM 对话 + embedding | ✅（缺了只能启动不能对话） |
| Python + venv | 3.13（`doc-processor/.venv`） | 文档智能解析 | 可选（缺了自动降级 Tika） |

> **库初始化**：首次使用需执行建表脚本（CMD 中在项目根目录执行）
> `D:\PostgreSQL\bin\psql -U postgres -d ecom_agent -f src\main\resources\db\init.sql`
> （幂等，可重复执行；已含订单/会话/工单/评估等全部表和索引）

---

## 二、服务拓扑

```
浏览器 localhost:5173 (Vite 前端)
        │  proxy /chat /stats /conversations /eval /handoff /kb /confirm
        ▼
后端 localhost:8080 (Spring Boot)
        ├─→ PostgreSQL localhost:5432 (ecom_agent)
        └─→ doc-processor localhost:8000 (可选，文档解析)
```

| 服务 | 端口 | 角色 | 缺失影响 |
|---|---|---|---|
| PostgreSQL | 5432 | 全部数据 | 后端启动即失败 |
| 后端 | 8080 | API | 前端全部请求失败 |
| 前端 | 5173 | 界面 | 无法访问 |
| doc-processor | 8000 | 文档解析增强 | 入库降级 Tika，`flags=tika_fallback` |

## 三、启动步骤（按顺序）

> ⚠️ **命令环境**：以下命令默认在 **Windows CMD** 中执行（反斜杠路径 + `findstr` + `set`）。
> 若用 **PowerShell**：`set VAR=值` 改成 `$env:VAR="值"`，`findstr` 同样可用（PowerShell 也支持 `Select-String`）。
> 若用 **Git Bash**：`cd` 用正斜杠、环境变量用 `export`。

### 第 0 步：确认 PostgreSQL 已启动

本机 PG 通常是 Windows 服务，开机自启。确认方式：

```cmd
netstat -ano | findstr ":5432" | findstr "LISTENING"
```

有输出 = 已启动。没起来则启动服务：

```cmd
net start postgresql-x64-17
```

> 服务名以实际为准（可在「服务」里搜 postgres 查看，通常形如 `postgresql-x64-17`）。

### 第 1 步（可选）：启动 doc-processor

> 不启动也能用，入库会走 Tika 兜底（`flags=tika_fallback`），
> 但标题层级/表格/工作流结构会丢失，检索质量略降。

```cmd
cd /d D:\Code\java\Spring_agent\doc-processor
.venv\Scripts\python.exe -m uvicorn app.main:app --port 8000
```

看到 `Uvicorn running on http://127.0.0.1:8000` 即成功。

### 第 2 步：IDEA 启动后端

1. 打开项目 `D:/Code/java/Spring_agent`
2. 找到主类 `com.ecomagent.SpringAgentApplication`，右键 **Run**
3. 确认 Run Config 环境变量含 `DASHSCOPE_API_KEY`（你的 `.idea` 配置里已存）
4. 看到这行即成功：

```
Started SpringAgentApplication in 4.2 seconds
Tomcat started on port 8080
```

> ⚠️ IDEA 启动后端时，**不要**在 IDEA 之外的终端同时用 `mvn spring-boot:run` 起后端，
> 否则 8080 冲突。

### 第 3 步：启动前端

在 **`frontend` 目录**打开 CMD 执行：

```cmd
cd /d D:\Code\java\Spring_agent\frontend

:: 指定 npm 缓存目录（沙箱/受限环境必需；普通环境可省略）
set npm_config_cache=D:\Code\java\Spring_agent\.npm-cache

:: 若系统已装 node 可直接 npm；否则先指向托管版 node
set PATH=C:\Users\kiana\.workbuddy\binaries\node\versions\22.22.2;%PATH%

npm run dev
```

> PowerShell 用户把 `set` 换成：`$env:npm_config_cache="D:\Code\java\Spring_agent\.npm-cache"`

看到这行即成功：

```
VITE v6.4.3  ready in 5728 ms
➜  Local:   http://localhost:5173/
```

浏览器访问 **http://localhost:5173**（前端通过 Vite 代理自动转发 API 到 8080）。

## 四、验证清单

后端起来后，依次确认（CMD 中执行，或直接用浏览器/前端页面验证）：

```cmd
:: 1. 健康检查（UP + 无降级）
curl http://localhost:8080/chat/health

:: 2. 真实订单查询（种子数据 ORD-1001 = 京东/已签收；URL 已编码，CMD 中文不乱码）
curl "http://localhost:8080/chat/stream?message=%E6%9F%A5%E4%B8%80%E4%B8%8B%E8%AE%A2%E5%8D%95ORD-1001&conversationId=t1&platform=jd"

:: 3. 统计/历史/评估/工单接口
curl http://localhost:8080/stats/overview
curl http://localhost:8080/conversations
curl http://localhost:8080/eval/summary
curl http://localhost:8080/handoff
```

前端页面：聊天窗 `/chat`、坐席确认台 `/confirm`、转人工工单 `/handoff`、知识库上传 `/kb`、
咨询态势看板 `/dashboard`、对话记录 `/history`、RAG 评估台 `/eval`。

## 五、常见坑速查

| 现象 | 根因 | 解决 |
|---|---|---|
| 后端起不来，报 `Port 59894 already in use` | 沙箱注入了 `SERVER__PORT` 环境变量覆盖了 8080 | CMD：`set SERVER__PORT=` 清空；或启动加 `--server.port=8080` |
| `npm install` / `npm run dev` 报 ENOENT 缓存错误 | 系统 npm 缓存目录被拦截 | CMD：`set npm_config_cache=D:\Code\java\Spring_agent\.npm-cache` |
| 聊天报 403 / 额度耗尽 | DashScope 免费额度用完 | 充值或关"仅用免费额度"；判定类已切 glm-5.2（2026-09-03 后不再依赖 qwen-turbo 免费池） |
| 前端「基础问答模式」badge 常亮 | 部分能力降级（模型 403 等） | 看 `/chat/health` 的 `degraded` 数组定位 |
| 上传文档后 IDEA 无日志 | 旧版代码成功路径没打日志（已修） | 重启后端，成功会打印 `知识库入库成功: docId=...` |
| 上传报 `flags=tika_fallback` | doc-processor 没起，走了 Tika 兜底 | 启动 doc-processor（第 1 步） |
| 检索一直未命中、自动转人工 | 知识库被清空（A 方案清理） | 重新上传 `kb-samples/` 里的文档 |
| 后端改了代码但不生效 | JVM 加载了旧 class（无 DevTools） | 停掉旧进程 → rebuild → 重启 |
| 改了构造器签名后运行报 `NoSuchMethodError` | 增量编译残留旧签名的测试 class | 跑一次 `mvn -o clean test` |
