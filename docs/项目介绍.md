# 电商客服 Agent（Spring Agent）— 项目详细介绍

> 一个基于 **Spring AI + PostgreSQL(pgvector) + Vue3** 的电商智能客服系统，覆盖「RAG 知识问答 → 订单工具调用 → 坐席确认 → 转人工工单 → 运营评估」的完整闭环。

---

## 一、项目定位

电商场景下，客服要回答大量重复性问题（退货政策、物流、改地址、优惠券……），同时涉及**资金类写操作**（退款、改地址、发券）需要人工把关。本项目把这些能力组装成一个**可观测、可运营、有安全护栏**的智能体：

- **能答**：基于商家上传的知识库做检索增强问答（RAG），答案带可点击引用溯源。
- **能查**：接真实订单数据，能查订单状态、物流轨迹。
- **能办**：退款 / 改地址 / 发券——但**不直接执行**，走「坐席确认」人工护栏。
- **能兜底**：搞不定时自动转人工工单，带上对话上下文快照。
- **能运营**：统计看板、历史会话、CSV 导出、RAG 评估台、知识库管理、未命中问题挖掘。

核心价值不在"又一个聊天机器人"，而在**工程可靠性**：把 LLM 应用里最容易翻车的点（静默降级、幻觉编造、资金操作失控）逐一用机制兜住。

## 二、功能全景

| 模块 | 功能 | 关键入口 |
|---|---|---|
| **对话** | SSE 流式回答、Markdown 渲染、引用溯源、多轮记忆 | `/chat/stream` |
| **RAG 知识库** | 文档上传 → 解析 → 分块 → 向量化；混合检索（向量 + BM25） | `/kb/upload` |
| **工具调用** | 查订单（接真数据）、退款 / 改地址 / 发券（需确认） | Tool Calling |
| **坐席确认台** | 写操作待确认队列、改参确认、驳回 | `/confirm/*` |
| **转人工工单** | 按优先级自动建单、上下文快照、坐席认领关闭 | `/handoff` |
| **知识库管理** | 多知识库、文档列表/详情/删除/重处理、检索测试、统计 | `/kb/documents` 等 |
| **运营看板** | 会话统计、平台维度、历史会话、CSV 导出 | `/stats` `/conversations` `/export` |
| **RAG 评估** | 命中率/引用越界/成本采集、未命中挖掘、语义聚类 | `/eval/*` |
| **健康监控** | 降级能力列表透出 | `/chat/health` |

## 三、系统架构

```
                浏览器 (Vue3 + Element Plus, Vite :5173)
                  │  proxy /chat /kb /confirm /stats /conversations /eval /handoff
                  ▼
          Spring Boot 后端 (:8080)
     ┌────────────────────────────────────────┐
     │  api 层      Controller（信封 ApiResponse） │
     │  agent 层    ChatService 编排（流式 SSE）    │
     │             ├─ SignalDetector  信号检测      │
     │             ├─ SessionState    状态提取(L2)  │
     │             ├─ StateMachine    主动澄清      │
     │             ├─ QueryRewrite    查询改写(L1)  │
     │             ├─ RetrievalPipeline 混合检索    │
     │             ├─ OutputGuardrail  输出护栏     │
     │             └─ ConfirmationService 确认护栏 │
     │  rag 层      入库/检索/评估/缺口/聚类/知识库管理│
     │  order 层    订单查询 + 写操作执行            │
     │  conversation/handoff/eval 层 落库/工单/评估  │
     │  common 层   上下文/降级/异常/PII/日志        │
     └───────────────┬────────────────────────────┘
          ┌─────────┴──────────┐
   PostgreSQL + pgvector    doc-processor(FastAPI :8000)
   (订单/会话/评估/向量)      (文档解析, 可降级 Tika)
          │
   DashScope (glm-5.2 对话 / text-embedding-v3 向量)
   DeepSeek (可选降级 LLM)
```

## 四、核心模块详解

### 1. 对话编排 —— `ChatService`

一次用户提问的完整流水线（每步都有降级与日志）：

```
用户消息
 ├─ 落库（首次建会话、设标题）
 ├─ SignalDetector：纯规则识别高频问题（退款/查单/投诉…），不依赖 LLM
 ├─ SessionState 提取：LLM 增量提取 intent/orderId/emotion（best-effort，失败降级）
 ├─ StateMachine：状态机决策，缺关键信息时主动澄清
 ├─ QueryRewrite：LLM 改写检索句（失败用原句）
 ├─ RetrievalPipeline：混合检索（向量 + BM25），返回候选文档 + 引用编号
 ├─ LLM 生成（流式，逐 token 推送）
 ├─ OutputGuardrail：越界拒答 + LLM-as-Judge 事实一致性校验
 ├─ 转人工判定：用户要求 > 情绪负面 > 事实校验失败 > 检索未命中
 └─ 流结束：会话落库 + RAG 评估采集（命中率/越界/成本）
```

### 2. 工具调用 —— Tool Calling（Function Calling）

- **只读工具**（`OrderQueryTool`）：LLM 直接执行，查真实订单。
- **写操作工具**（`RefundTool` / `AddressChangeTool` / `CouponTool`）：标注 `@ConfirmRequired`，LLM 调用时**不真正执行**，而是落一条 `pending_action(status=pending)`，返回"已提交待坐席确认"。真正执行在坐席点确认之后。

### 3. 确认护栏 —— `ConfirmationService`（项目亮点之一）

针对"LLM 误操作资金"的风险，设计了完整的写操作护栏：

- **幂等键**：同会话同参数重复请求返回同一条 pending，不重复建单。
- **双执行防护**：行级 `UPDATE ... WHERE status='pending'` 原子抢占，重复确认抛冲突。
- **超时 Reaper**：超过 5 分钟未确认自动过期。
- **结果回灌**：坐席确认后的执行结果写回消息流，用户能看到"已退款"。

### 4. 混合检索 —— `RetrievalPipeline`

向量检索（语义相似）+ BM25（关键词精确）双路召回，再做重排/去重，兼顾"语义相近"和"精确命中"。

### 5. 静默降级治理 —— `DegradationFlags`（项目亮点之一）

LLM 链路里最容易翻车的是**静默失效**：某个子能力（状态提取、查询改写、护栏、embedding）失败后被 try-catch 吞掉，系统"看起来正常"实际已退化。本项目用一张带 TTL 的降级标志表：

- 每个能力失败时 `mark`，成功时 `clear`；
- 透出到 `/chat/health` 和前端"基础问答模式"badge；
- 用户/运维一眼能看到"护栏已关闭"而不是被蒙在鼓里。

### 6. 引用溯源 + 文档阅读器

- 回答中的 `[n]` 是**可点击上标**，点击打开文档阅读器；
- 阅读器展示"被引用段落" + "原文全文（命中段高亮定位）"；
- 映射关系：`[n] → citations[index] → (docId, chunkIndex) → 原文段落`。

### 7. RAG 评估闭环 + 语义聚类

- 每轮对话流结束采集：检索命中率、引用越界数、token 成本（`rag_eval` 表）。
- 未命中问题（hit=false）聚合出"该补哪些文档"的缺口清单。
- **语义聚类**：对未命中 query 做 embedding，按余弦相似度贪心聚类——"7天无理由""过了7天还能退吗"聚成一类，反映的是知识盲区而非字面重复。

### 8. 转人工工单 —— `HandoffService`

按优先级触发（用户明确要求 > 情绪负面 > 事实校验失败 > 检索未命中），建单时快照对话上下文，坐席可在工单页认领、关闭。

## 五、技术栈清单

| 层 | 技术 |
|---|---|
| 后端框架 | Spring Boot 3.5.3、Spring AI 1.0.0 GA |
| 数据库 | PostgreSQL 15+、pgvector（向量存储） |
| LLM | DashScope 兼容接口：glm-5.2（对话/判定）、text-embedding-v3（向量）；DeepSeek-V3（可选降级） |
| 文档处理 | doc-processor（Python FastAPI）、Apache Tika 兜底 |
| 前端 | Vue3（组合式 API）、Element Plus、Vite、markdown-it、docx/xlsx（导出） |
| 构建 | Maven（离线模式）、npm |
| 可观测 | SLF4J + Logback（三段式日志）、Spring Actuator |

## 七、目录结构（后端核心）

```
src/main/java/com/ecomagent/
├── api/           # Controller 层（chat/kb/confirm/handoff/stats/eval/export）
├── agent/         # 对话编排、信号检测、状态机、护栏、确认服务

├── order/         # 订单查询 + 写操作执行器
├── conversation/  # 会话/消息落库、统计、导出
├── handoff/       # 转人工工单
├── eval/          # RAG 评估、语义聚类
├── config/        # 模型配置、ChatClient、PgVector 配置
└── common/        # 上下文、降级标志、全局异常、PII 脱敏、日志过滤器
```
